# Облачный дневник FORMA

GitHub Pages размещает интерфейс. Supabase хранит личные дневники в PostgreSQL и управляет входом по электронной почте и паролю. Без настроенного проекта приложение продолжает работать локально и прямо показывает, что облако не подключено.

## Подключение

1. В своём аккаунте Supabase создайте **отдельный** проект FORMA на бесплатном тарифе. Пароль базы храните у себя: приложению он не нужен.
2. Примените `supabase/migrations/202610180001_journal.sql` через подключённый плагин Supabase либо SQL Editor. Миграция создаёт таблицу и функцию сохранения с проверкой версии. Включена RLS: пользователь видит и меняет только собственный дневник. Анонимный доступ и опасные табличные привилегии отозваны.
3. В Authentication → URL Configuration укажите Site URL `https://nikolaikryshnev.github.io/gym/` и разрешённые Redirect URLs для этого адреса. Если используете другую публикацию, добавьте её точный адрес отдельно. Не добавляйте широкие маски для чужих доменов.
4. Включите Email/Password. Для доставки подтверждений и восстановления пароля настройте собственный SMTP: стандартная отправка Supabase ограничена и предназначена для тестирования. Не отключайте подтверждение адресов в общедоступном приложении ради обхода ограничения.
5. В Connect возьмите **Project URL** и **publishable key** (либо старый `anon` key). Они предназначены для браузера. Передайте JSON с полями `url` и `publishableKey` на stdin `node scripts/configure-cloud.mjs`. Скрипт отклоняет секретные ключи. Никогда не помещайте `service_role`, `sb_secret_`, пароль PostgreSQL, access/refresh token в GitHub или файлы сайта.
6. Обновите содержимое `dist` на GitHub Pages. Для обновления SDK после установки зависимостей используется `npm run build:vendor`; подключение к CDN при работе приложения не требуется.

## Первый вход и перенос

На основном устройстве откройте Настройки → Облачный дневник, создайте аккаунт дневника (он отличается от аккаунта панели Supabase), подтвердите почту и войдите. «Отправить этот дневник» переносит текущие реальные записи в пустое облако. Демонстрационная история не отправляется; приложение предложит начать свой дневник. Если в облаке уже есть данные, первоначальная отправка не может их заменить.

На телефоне войдите в тот же аккаунт и выберите «Открыть облачный дневник». Прежний локальный дневник сохраняется отдельно, перед заменой создаётся дополнительная копия. Для переноса с другого адреса сайта сначала скачайте JSON на старом адресе и импортируйте его на новом: браузеры не делят хранилище между адресами.

## Синхронизация и ограничения

- Все данные дневника, включая незавершённую тренировку, хранятся одним документом JSONB на пользователя. Программы по умолчанию сохраняют схему 2 разминки + 3 рабочих подхода.
- Для каждого аккаунта и проекта выделена отдельная локальная копия. Выход открывает гостевой дневник этого браузера; неотправленные изменения аккаунта сохраняются для следующего входа. Выход не стирает копии с доверенного личного устройства.
- Изменения сначала записываются локально. Отправка выполняется после паузы ввода, затем каждые 30 секунд и при возвращении в приложение/восстановлении сети. Во время редактирования поля или открытого диалога фоновая синхронизация ждёт. При закрытом приложении отправки нет.
- Запись в PostgreSQL проверяет номер версии атомарно. Если два устройства изменили дневник, интерфейс предлагает выбрать версию. Автоматического объединения записей нет. Перед выбором сохраняется заменяемая версия (последние 3 копии в этом браузере; кнопка «Копия до замены» скачивает последнюю).
- Бесплатный тариф Supabase имеет квоты и может приостанавливать проект после недели бездействия. В этом случае возобновите его в панели сервиса; приложение сохраняет локальные записи. Гарантии вечного бесплатного обслуживания нет. Актуальные условия: https://supabase.com/pricing.
- Облако не заменяет отдельную резервную копию JSON. Автоматические серверные резервные копии не входят в текущий бесплатный тариф.

## Проверка перед включением

`npm test` проверяет перенос, офлайн-очередь, перезапуск, разные аккаунты, повреждённые данные, конкурирующие записи и сохранение ввода во время отправки. `npm run check` проверяет синтаксис.

После подключения реального проекта дополнительно проверьте: регистрацию/подтверждение почты, вход и восстановление пароля с разрешённого адреса, сохранение и чтение с двух устройств; запрет анонимного чтения и чтения чужой записи; отклонение устаревшего номера версии. До применения миграции и этой проверки живая облачная база не считается подключённой.
